# 14. Model report — handoff for review and improvement

Purpose: give another engineer the facts needed to check the burst detector and improve it without touching the LogSeal core. Written 2026-11-25 after commit `a41fdbc`.

## 1. What the model is

The burst detector is a **secondary feature**. The integrity proof uses hashes and vaults. The model never changes a verdict or a console banner.

- Algorithm: `sklearn.ensemble.IsolationForest(random_state=42)`.
- Input: 18 numeric features per 10 s window.
- Threshold: the 1st percentile of scores from 288 unseen benign validation windows. The test set does not set the threshold.
- Rule baseline: alarm when one IP sends at least 3 login failures in a 10 s window. Training derives 3 from the validation block as the highest benign per-IP failure count plus one, with a floor of 3.
- Output: `ml.flag_windows()` returns scored windows for the console activity chart.
- Data: synthetic events from our own `gen.py`. Nothing here uses real customer logs.

## 3. Features

One row per 10 s window. `ml.FEATURES` is the single list of names. `tests/test_ml.py` asserts that the list has 18 unique names.

| Group | Features |
|---|---|
| Event counts | `login_ok`, `login_fail`, `logout`, `file_read`, `file_write`, `sudo`, `config_change` |
| Window totals | `window_total`, `unique_src_ip`, `unique_user`, `fail_fraction` |
| Per-IP signal | `max_ip_fail`, `top_ip_fail_share` |
| Timing | `fail_gap_mean`, `fail_gap_std` |
| Spread | `user_entropy`, `ip_entropy` |
| Sequence | `fail_then_success` |

Rows with an unparseable timestamp are skipped. The window key is `epoch_seconds // 10 * 10`.

## 7. Research notes

Checked on 2026-11-25:

- scikit-learn outlier detection documentation: `score_samples` gives the raw score. The `contamination` float sets an offset so a given share of training samples is flagged. `average_precision_score` gives a threshold-free ranking score. See https://scikit-learn.org/stable/modules/outlier_detection.html and https://scikit-learn.org/stable/modules/model_evaluation.html
- MITRE ATT&CK T1110.003 lists detection analytics for a high volume of authentication failures from one IP or across many accounts in a defined time window. See https://attack.mitre.org/techniques/T1110/003/

These sources support the per-IP rule. They do not validate our synthetic dataset. Treat them as design guidance, not as a benchmark for LogSeal.

## 8. No LLM in the integrity path

Do not send raw log lines to an LLM. The log contains attacker-controlled text, so it creates a prompt injection path. A probabilistic model also weakens the claim that the verdict comes from hashes and vaults. If the team later wants an optional “explain this alert” panel, pass only structured fields, label the text as advisory, and keep a template fallback for offline demo use. That work comes after the demo and rehearsals.

## 10. Improvement plan

1. Reduce forest false alarms with a cost chosen on the validation block. Do not touch the test set.
2. Evaluate at burst level first. One alarm per burst is easier to explain than 12 window hits.
3. Compare against the rule on new generated scenes: slow spray, distributed spray, and a burst mixed with heavy benign traffic.
4. Add replay from a saved real-format log. Keep the labels separate from the synthetic labels.
5. Let P3 review the `app.py` message and the chart before the projector test.
6. Keep the claim narrow: synthetic data, our generator, secondary feature, measured today.

Generated files stay out of git. `dataset/`, `model.joblib`, `metrics.json`, `metrics_detail.json`, `metrics_sweep.json` and `.run/` are ignored.
